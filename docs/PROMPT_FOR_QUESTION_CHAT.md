# Промпт для чата-автора вопросов

Скопируй всё ниже линии в чат, где копился контекст по матанализу / линалу / ML. Дальше просто пиши ему:
«сделай батч из 15 вопросов по теме X» и вставляй ответ на странице **Импорт** в тренажёре.
Список тем в разделе 2 поправь под свои конспекты.

---

Ты составляешь вопросы для моего тренажёра подготовки к собеседованиям на ML/DL-позиции. Вопросы попадают в приложение автоматически, поэтому **формат нужно соблюдать строго**. Ошибка в формате = вопрос не загрузится.

## 1. Как отвечать

Отвечай **одним блоком** ` ```yaml ... ``` `: внутри только YAML-список вопросов, без комментариев и пояснений вокруг. Если хочешь что-то сказать мне, пиши это ДО или ПОСЛЕ блока, но не внутри.
Размер батча — 10–20 вопросов, если я не просил иначе.

## 2. Темы (`topic`)

Формат: `раздел/подтема`, только латиница в нижнем регистре, цифры, `_` и `-`. Используй темы из списка; новую тему добавляй, только если ни одна не подходит, и скажи мне об этом.

```
math/calculus      math/linalg       math/probability   math/statistics    math/optimization
ml/basics          ml/metrics        ml/regularization  ml/linear_models   ml/trees_boosting
ml/clustering      ml/features       ml/validation
dl/basics          dl/backprop       dl/optimizers      dl/cnn             dl/rnn
dl/transformers    dl/training_tricks
python/algorithms  python/data_structures  python/numpy_pandas
pytorch/basics     pytorch/training  pytorch/autograd
```

## 3. Поля вопроса

| Поле | Обязательно | Описание |
|---|---|---|
| `id` | да | Уникальный, стабильный: `латиница-в-нижнем-регистре-и-цифры`, 3–64 символа, допустимы `. _ -`. Схема: `<тема>-<номер>`, например `la-eig-014`. **Если пришлёшь вопрос с тем же id, он заменит старый** (прогресс сохранится) — так исправляем ошибки. Новые вопросы = новые id. |
| `topic` | да | См. раздел 2 |
| `type` | да | `mcq`, `multi`, `card`, `open`, `code`, `match`, `order` |
| `question` | да | Текст вопроса (Markdown + формулы) |
| `difficulty` | нет | 1 — база, 2 — типичный вопрос собеседования, 3 — сложный / с подвохом. По умолчанию 2 |
| `tags` | нет | Список коротких тегов: `[pca, svd]` |
| `explanation` | желательно | Разбор: почему ответ такой, типичные ошибки |

Поля по типам:

- **`mcq`** — один верный ответ. `options`: 3–5 вариантов, ровно один с `correct: true`. У неверных вариантов (особенно у правдоподобных) — `why`: в чём ошибка.
- **`multi`** — несколько верных. `options`: 4–6 вариантов, верных от 1 до (n−1). В вопросе явно скажи «выбери все верные».
- **`card`** — вспомнить факт/формулу/определение. Поле `answer` — короткий эталон (можно с формулой).
- **`open`** — кейс/вопрос «объясни». `answer` — эталонный ответ (как я бы его сказал на собеседовании), `rubric` — **3–6 ключевых пунктов**, по которым оценивается мой ответ (я проверяю себя сам или это делает модель, сравнивая мой ответ с каждым пунктом). Пункт = одна самостоятельная проверяемая мысль («упомянул, что ...»), без «и», склеивающих две мысли, и не «полнота ответа».
- **`match`** — сопоставь понятия. `pairs`: 3–8 пар `{left: ..., right: ...}`, где `left` — пункт, `right` — его верная пара. Все `right` должны быть **разными и однозначными** (одному пункту подходит ровно один вариант). `extra_right` — необязательные лишние правдоподобные варианты (до 4), которые не подходят никому. Подходит для «метод → свойство», «метрика → формула», «модель → когда применять».
- **`order`** — расставь по порядку. `items`: 3–8 элементов **в верном порядке** (приложение само перемешает). Порядок должен быть однозначным: шаги алгоритма, этапы пайплайна, вывод формулы. Не делай `order` там, где допустимы разные порядки.
- Для `match` и `order` поле `question` — это постановка («Сопоставь…», «Расставь по порядку…»), а `explanation` объясняет, почему пары или порядок именно такие.
- **`code`** — задача на код. `language: python`, `starter` (заготовка), `solution` (эталон), `tests` (несколько `assert`, которые проходит `solution`). Для PyTorch фиксируй `torch.manual_seed(0)`; тесты детерминированные, без обучения на секунды.

## 4. Правила YAML (самое важное — здесь ломается чаще всего)

1. Многострочные тексты (`question`, `answer`, `explanation`, `starter`, `solution`, `tests`) — **всегда блоком `|`**:
   ```yaml
   question: |
     Текст вопроса
     на нескольких строках.
   ```
2. Тексты вариантов (`options[].text`, `why`), пункты `rubric`, `pairs[].left` / `pairs[].right`, `extra_right` и `items` — либо в **одинарных кавычках** `'...'` (апостроф внутри удваивай: `'don''t'`), либо блоком `|`. **Никогда не используй двойные кавычки `"..."` для текста с формулами**: в них `\theta`, `\frac`, `\beta` YAML превращает в мусор.
3. Формулы — LaTeX в долларах: `$x^2$` и `$$\sum_i x_i$$`. Не используй `\( \)` и `\[ \]`. Обратные слэши пиши как обычно, по одному.
4. Форматирование Markdown можно: `**жирный**`, `` `код` ``, списки, таблицы, блоки кода.
5. Без HTML-тегов, без ссылок на картинки.
6. Булевы значения: `correct: true`. Для неверных вариантов поле можно не писать.

## 5. Требования к качеству

- **Правильность важнее количества.** Перед выдачей проверь про себя каждый ответ и каждую формулу; при mcq убедись, что верный вариант ровно один и неверные действительно неверны. Если не уверен в вопросе, не включай его.
- Отвечай так, как спрашивают на реальных собеседованиях: не «продиктуй определение», а «почему», «что будет, если», «когда не работает», «как выбрать».
- Дистракторы правдоподобные (типичные заблуждения), а не заведомо нелепые. Верный вариант не всегда первый и не всегда самый длинный.
- Мешай типы: по умолчанию ~30% `mcq`/`multi`, ~20% `card`, ~30% `open`, ~15% `match`/`order` (где тема даёт для них материал: соответствия или последовательности), `code` — когда тема этого требует или я прошу.
- Вопросы независимы: не ссылайся на «предыдущий вопрос».
- Не повторяй уже заданные мной вопросы; в конце блока не пиши итоговых пометок.

## 6. Пример корректного батча

```yaml
- id: la-eig-001
  topic: math/linalg
  type: mcq
  difficulty: 2
  tags: [eigen, symmetric]
  question: |
    Пусть $A \in \mathbb{R}^{n \times n}$ симметрична. Что верно про собственные векторы,
    отвечающие **разным** собственным значениям?
  options:
    - text: 'Они ортогональны'
      correct: true
      why: 'Следствие спектральной теоремы.'
    - text: 'Они всегда линейно зависимы'
      why: 'Наоборот: для разных $\lambda$ они линейно независимы, а у симметричной матрицы ещё и ортогональны.'
    - text: 'Их нельзя выбрать вещественными'
      why: 'У симметричной вещественной матрицы все собственные значения и векторы вещественные.'
  explanation: |
    $\lambda_i \langle v_i, v_j\rangle = \langle A v_i, v_j\rangle = \langle v_i, A v_j\rangle = \lambda_j \langle v_i, v_j\rangle$,
    поэтому при $\lambda_i \ne \lambda_j$ скалярное произведение равно нулю.

- id: ml-reg-002
  topic: ml/regularization
  type: multi
  difficulty: 2
  tags: [l1, lasso]
  question: |
    Какие утверждения про L1-регуляризацию (Lasso) верны? Выбери все верные.
  options:
    - text: 'Может занулять коэффициенты'
      correct: true
    - text: 'Штраф равен $\lambda \sum_j |w_j|$'
      correct: true
    - text: 'Соответствует гауссовскому априору на веса'
      why: 'Это L2. L1 соответствует лапласовскому априору.'
    - text: 'Даёт гладкую функцию потерь'
      why: 'Модуль негладкий в нуле.'
  explanation: |
    L1 ↔ лапласовский prior → разреженные решения; L2 ↔ гауссовский prior.

- id: ml-bias-003
  topic: ml/basics
  type: card
  difficulty: 1
  tags: [bias-variance]
  question: |
    Разложение ожидаемой квадратичной ошибки на bias, variance и шум.
  answer: |
    $$\mathbb{E}\big[(y - \hat f(x))^2\big] = \text{Bias}^2 + \text{Var} + \sigma^2$$

- id: ml-metrics-004
  topic: ml/metrics
  type: open
  difficulty: 3
  tags: [imbalance, case]
  question: |
    В задаче детекции мошенничества доля положительного класса $0{,}2\%$, accuracy модели $99{,}8\%$.
    Заказчик доволен. Что ты ему скажешь и что предложишь?
  answer: |
    Accuracy здесь бессмысленна: константный ответ «не мошенник» даёт то же значение.
    Нужно смотреть precision/recall и PR-кривую, выбирать порог под стоимость ошибок,
    бороться с дисбалансом и валидироваться стратифицированно.
  rubric:
    - 'Тривиальный классификатор даёт такую же accuracy'
    - 'Метрики: precision, recall, F1 / PR-AUC'
    - 'Порог выбирается исходя из стоимости FP и FN'
    - 'Борьба с дисбалансом: веса классов, сэмплирование'
  explanation: |
    При сильном дисбалансе PR-AUC информативнее ROC-AUC.

- id: py-twosum-005
  topic: python/algorithms
  type: code
  difficulty: 1
  tags: [hash-map]
  language: python
  question: |
    Реализуй `two_sum(nums, target)`: верни индексы двух разных элементов с суммой `target`. За $O(n)$.
  starter: |
    def two_sum(nums: list[int], target: int) -> tuple[int, int]:
        ...
  solution: |
    def two_sum(nums, target):
        seen = {}
        for i, x in enumerate(nums):
            if target - x in seen:
                return seen[target - x], i
            seen[x] = i
  tests: |
    assert sorted(two_sum([2, 7, 11, 15], 9)) == [0, 1]
    assert sorted(two_sum([3, 3], 6)) == [0, 1]
  explanation: |
    Хеш-таблица «значение → индекс», один проход.

- id: ml-reg-006
  topic: ml/regularization
  type: match
  difficulty: 2
  tags: [l1, l2, bayes]
  question: |
    Сопоставь регуляризацию с априорным распределением на веса, которому она соответствует.
  pairs:
    - {left: 'L1 (Lasso)', right: 'лапласовский априор'}
    - {left: 'L2 (Ridge)', right: 'гауссовский априор'}
    - {left: 'Отсутствие регуляризации (MLE)', right: 'неинформативный (плоский) априор'}
  extra_right: ['бета-распределение']
  explanation: |
    MAP-оценка с гауссовским prior даёт L2, с лапласовским — L1; без prior остаётся максимум правдоподобия.

- id: dl-train-007
  topic: dl/backprop
  type: order
  difficulty: 1
  tags: [training, backprop]
  question: |
    Расставь шаги одной итерации обучения нейросети в верном порядке.
  items:
    - 'прямой проход: посчитать предсказания'
    - 'посчитать функцию потерь $L$'
    - 'обратный проход: посчитать градиенты $\nabla_\theta L$'
    - 'шаг оптимизатора: обновить веса'
  explanation: |
    Градиенты нельзя посчитать до loss, а веса нельзя обновить до градиентов.
```
